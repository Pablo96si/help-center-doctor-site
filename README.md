# Help Center Doctor: marketing, docs and legal site

Static HTML, no build step, no external resources. Every page is a folder with an `index.html`; all links are relative, so the site works at a domain root and under a sub-path such as `https://<user>.github.io/<repo>/`.

```
site/
  index.html                 landing page
  404.html                   self-contained not-found page
  robots.txt, sitemap.xml    absolute URLs use the placeholder domain (update them)
  assets/site.css, site.js   the only stylesheet and script (mobile nav)
  assets/logo.svg|png        logo (logo.png is the Open Graph image)
  assets/shots/*.png         screenshots generated by `npm run screenshots`
  demo/                      the real app on sample data (built by `npm run screenshots`; app.js/app.css are gitignored)
  features/ pricing/ docs/ docs/<screen>/ privacy/ terms/ support/ changelog/ compare/
  zendesk-broken-links/ zendesk-find-and-replace/ export-zendesk-articles-to-pdf/ zendesk-article-templates/
```

## Before deploying

1. Build the demo bundle so `site/demo/app.js` and `app.css` exist (they are gitignored): from the repository root run `npm run screenshots` (rebuilds `site/demo` and the screenshots) or the demo build step it wraps.
2. Check: `node scripts/check-site.js site` verifies every internal link resolves, each page has a doctype, `lang`, title and exactly one `h1`, and that no `http://` resource is referenced.

## Deploy to GitHub Pages (one command)

Push the contents of `site/` to the root of a repository whose Pages source is "main, / (root)". From the repository root, with `gh` signed in:

```bash
git subtree push --prefix site origin gh-pages
```

Then in the repository settings choose Pages > Build and deployment > Source: "Deploy from a branch", Branch: `gh-pages`, Folder: `/ (root)`. Repeat the command after every change. The site is then at `https://<user>.github.io/<repo>/`, and the 404 page detects that sub-path on its own.

If you prefer a separate repository that holds only the site:

```bash
git init site-only && cp -r site/. site-only/ && cd site-only && git add -A && git commit -m "Site" && gh repo create help-center-doctor-site --public --source . --push
```

and set Pages to "main, / (root)". For a custom domain, add a `CNAME` file containing the domain to `site/` and configure DNS as GitHub describes.

## Deploy to Cloudflare Pages (one command)

With Wrangler installed and signed in (`npx wrangler login`):

```bash
npx wrangler pages deploy site --project-name help-center-doctor
```

Cloudflare uploads the `site` directory as is. The first run creates the project; later runs publish new versions. Attach the custom domain in the Cloudflare dashboard under Pages > project > Custom domains. Cloudflare Pages serves `404.html` automatically for missing paths.

## After choosing the domain

Replace the placeholder `https://helpcenterdoctor.app` and `support@helpcenterdoctor.app` everywhere:

| File | What to update |
|---|---|
| `site/**/index.html` | `<link rel="canonical">`, `og:url`, `og:image`; the support address in footers and legal pages (`grep -rl helpcenterdoctor.app site`) |
| `site/sitemap.xml`, `site/robots.txt` | absolute URLs |
| `apps/help-center-doctor/manifest.json` | `author.email`, `author.url`, `termsConditionsURL` |
| `marketplace/listing.md` | privacy, terms, docs and demo URLs, support email; then run `node scripts/sync-listing.mjs` to copy the fields into `translations/en.json` |
| Marketplace Portal | privacy policy URL, support email, author URL |

A single search and replace over the repository covers all of it:

```bash
grep -rl "helpcenterdoctor.app" site apps marketplace --include="*.html" --include="*.xml" --include="*.txt" --include="*.json" --include="*.md" | xargs sed -i 's#helpcenterdoctor\.app#your-domain.example#g'
```

Then run `node scripts/sync-listing.mjs` so `en.json` matches the listing.
